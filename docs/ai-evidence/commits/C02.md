## 2. Objective

**Objective:** Establish the PostgreSQL and Java domain foundation for organization-scoped users and role-based authorization without implementing login or token handling.

**Research/engineering question:** What is the smallest enforceable schema and domain model that supports C03 authentication, prevents cross-organization identity ambiguity, and remains consistent with the approved ERD and RBAC matrix?

**Acceptance checkpoint:** An empty PostgreSQL database applies V1 and V2 successfully; `organizations`, `users`, `roles`, and `user_roles` exist; the four approved roles are seeded; tenant/email invariants and domain tests pass; no authentication API is added.

## 9. Corrections and rejected suggestions

- **Corrected:** retained stable role codes as the authorization contract while treating numeric seed IDs as internal implementation details.
- **Corrected:** added database checks and a case-insensitive composite unique index instead of relying only on Java validation.
- **Rejected:** H2 migration testing because PostgreSQL-specific `JSONB`, partial indexes, and expression indexes would not be validated faithfully.
- **Rejected:** adding authentication endpoints or Spring Security because those changes belong to C03.
- **Failed attempt:** local Maven verification could not start because the workspace exposes Java 17 and has no Maven executable, while the project requires Java 21. The unchanged Java 21 CI environment was used as the acceptance runner; this tooling limitation did not lead to weakening the project target.
