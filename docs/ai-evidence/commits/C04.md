## 2. Objective

**Objective:** Implement a persistent organization-scoped asset inventory with safe create, read, update, archive, search, filter, and pagination behavior.

**Engineering question:** How can DefenSME expose useful asset inventory operations while making cross-organization object access structurally unavailable and preserving archived history?

**Acceptance checkpoint:** The PostgreSQL asset migration applies; authorized roles can perform only their allowed operations; search/filter/pagination behave deterministically; active identifier uniqueness and archive semantics hold; cross-organization detail, update, and archive requests return `404`; the full CI suite passes.

## 3. Context classification

### Confirmed facts

- C04 requires asset schema, CRUD, search, pagination, organization isolation, and tenant-boundary integration tests.
- Asset records belong to one organization and must never be read or mutated through an ID-only lookup.
- Assets are archived rather than hard-deleted; mutating protected records creates audit events.
- The detailed RBAC matrix grants archive only to `IT_MANAGER`, while all authenticated roles may read and `IT_MANAGER`/`ANALYST` may create or update.
- API errors use the project problem-details contract and must not disclose foreign-organization resource existence.

### Assumptions

- `[ASSUMPTION]` Initial asset types are `SERVER`, `WORKSTATION`, `NETWORK_DEVICE`, `APPLICATION`, `CLOUD_SERVICE`, `DATABASE`, and `OTHER`.
- `[ASSUMPTION]` Initial criticalities are `LOW`, `MEDIUM`, `HIGH`, and `CRITICAL`.
- `[ASSUMPTION]` Search is case-insensitive over name and identifier; default stable ordering is name then UUID.
- `[ASSUMPTION]` Metadata is a JSON object limited to 25 top-level entries to keep the flexible field bounded.

### Open questions

- `[OPEN QUESTION]` PRD FR-ASSET-001 says ANALYST can archive, but the detailed RBAC matrix restricts archive to IT_MANAGER. C04 follows the least-privilege RBAC rule pending product reconciliation.
- `[OPEN QUESTION]` Asset-type-specific metadata schemas and validation are not yet defined.
- `[OPEN QUESTION]` Whether normal lists should exclude archived assets by default is not explicit; C04 returns all statuses unless a status filter is supplied.

## 9. Corrections and rejected suggestions

- **Corrected:** enforced tenant scope in repository lookup signatures rather than retrieving by asset ID and checking ownership afterward.
- **Corrected:** made archive a state transition with `archived_at`, not a delete operation, and allowed identifier reuse only after archive through a partial unique index.
- **Corrected:** validated optional owners through both user ID and organization ID to block cross-tenant ownership references.
- **Rejected:** accepting `organizationId` in asset requests because tenant context must come from the validated principal.
- **Rejected:** granting ANALYST archive based only on the broad functional-requirement sentence because the detailed RBAC matrix provides a more restrictive authorization rule.
- **Rejected:** returning `403` for a foreign asset ID because that confirms resource existence; the implementation returns `404`.
- **Rejected:** building C05 screens or C06 demo fixtures in this change because they have separate scheduled checkpoints.
- **Failed attempt:** the first Java 21 CI run compiled the implementation, applied Flyway V1→V4, and completed all five asset integration scenarios, but the unrelated `HealthControllerTest` slice failed to start. C04 introduced `AssetExceptionHandler`, whose constructor requires the application `Clock`; the narrow health slice already excluded the analogous auth advice but not the new asset advice. The correction excluded both unrelated advice classes from that isolated slice; full integration tests continue to load the real advice and security chain.
- **Local tooling limitation:** local Maven execution is unavailable because the workspace provides Java 17 and no Maven executable while the project targets Java 21. Verification is delegated to the configured Java 21 GitHub Actions runner without lowering the project runtime.
